# 账号、测试订单与交互验证

普通用户和超级消费者的新订单正常计价。开发者创建的订单仅限测试，不计入真实业务。不能因改名为 Peter 或提交 account_type / is_test 字段取得权限或改变计价。

Peter 为超级消费者，免频繁切换验证，正常计价，无后台权限；他现有两笔订单另行标记测试，之后新单正常计价。独立开发者可用登录名和密码进入顾客网页或商家后台，与管理员同权，包括查看订单、核款、修改菜单、导出、管理账号和清理记录。停用或取消开发者身份后，其后台会话在下次请求时立即失效。

开发者从顾客页或后台“代客下单”创建的订单，均由数据库强制标记 test_only。不能通过提交 is_test=false、恢复真实或直接修改测试标记进入真实营业。

订单列表默认只查询真实订单，真实金额、核款队列、备餐和配送汇总及默认 Excel 导出均不包含测试单。测试区可独立查看、模拟流程与导出，并标注“不计营业”。商家可填写原因后修改普通订单类型，操作记录保留；开发者创建的 test_only 订单不可转为真实单。修改账号身份不追溯修改历史订单。完整备份和七天清理覆盖两类记录；清理后简要历史保留测试标记。

普通用户（含访客）60 秒内超过 30 次页面、场次、分类或登录界面切换，触发五分钟有效的一次性计算题。已登录用户的拦截状态存储在云端，拦截期间订单和个人记录接口也要求验证；管理员、开发者和超级消费者免此验证。答题接口限频，每十分钟最多八次。计数不包含自动状态轮询，过期计数记录一天后清理。访客按 IP 的不可逆摘要计数，共用网络可能共同触发。计算题属于基础防刷，不是身份认证，也不能阻止自动解题或分布式攻击；注册限流、邀请码和可选 Turnstile 保持不变。

优惠券预留接口：

- `GET /api/admin/coupons`：仅管理员／已登录后台的开发者可访问，返回功能和规则未启用、可管理但不可发行的状态。
- `POST /api/admin/coupons/issue`：已预留同等管理权限，规则未配置前返回 409，不生成券、不产生折扣。
- 下单提交非空 `coupon_code` 时明确拒绝，不静默忽略优惠券，也不接受客户端修改金额。规则、折扣计算、有效期、使用范围和领取方式确认后再实现发行与核销。

所有显示金额仍由服务器按菜单计算；“测试”不是价格归零或退款状态，不改动原核款和履约记录。
