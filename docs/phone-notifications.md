# 微信 / 手机新单提醒

推荐在 Cloudflare 主站后台「手机提醒」选择微信服务号（pushplus）。老板继续使用微信：新单提醒 → 推送消息详情 →「点这里查看并处理订单」→ 登录后直接进入该单。网页无须常开，开发电脑关机不影响云端发送。已有网页提示音和 Bark iPhone 备用渠道保留。

## 绑定一次

1. 老板用自己的微信关注并登录 pushplus 推送加，在平台完成实名认证。
2. 创建一个用于点餐系统的消息 token，在商家后台填写并保存。此 token 对应平台绑定的微信，不能只填写任意个人微信号。
3. 发送测试通知，亲自确认微信收到、消息详情中的链接能打开后台，再勾选自动提醒并保存。测试不生成订单。

截至 2026-10-26，pushplus 文档列出实名普通账号每日 200 次微信请求、每分钟 5 次。首次实名认证收取平台认证服务费，以平台页面金额为准；这里没有购买会员、充值或接入收费短信。官方说明超过 48 小时或 5 条客服消息后转为模板消息，不等于必须每天激活。模板外观由微信和平台决定，可能先进入平台消息详情再点订单链接。锁屏是否弹出/响铃受微信、手机权限、静音和免打扰影响，不保证持续响铃或老板已读。

## 触发和可靠性

- 顾客正式提交真实订单才排队；草稿、只上传凭证、开发者和其他测试订单不通知。商家补录真实单也提醒。开通不补发历史订单。
- D1 触发器与正式提交事件同事务排队，订单 ID 唯一去重。Worker waitUntil 立即尝试，Cloudflare 每分钟 cron 补发/重试。保留的 Sites 网址支持提交时发送，未配置其独立定时器时重试依赖后续提交；优先在 Cloudflare 主站绑定。
- 微信本网站上限是过去 24 小时 180 次预留发送量，留出平台额度；间隔至少 15 秒，突发多单排队。平台额度按整个账号统计，其他工具仍会占用额度。网站不控制平台计费，也不会自动付费。
- Bark 按纽约自然日设 1–500 次上限。测试和失败重试都计数。达到限制只停止通知，订单不丢失。每次请求 8 秒超时，最多 3 次尝试，约 1 分钟、5 分钟后重试；6 小时前未发出的任务停止发送，不次日集中补发。
- 微信未实名、凭据无效、账号受限、积分不足等响应会暂停继续调用；修复平台账号后重新保存或测试恢复。异步回调报告失败时显示在记录中，不无限重发。
- 「平台已接收」只是接口接受；微信随机令牌保护的回调进一步更新为「平台报告已投递」或失败，仍不代表手机显示或老板已读。Bark 只有接口接受记录。网络模糊失败可能重复提醒同一订单，不声称端到端 exactly-once。
- 配置版本校验防止多人覆盖；换账号/渠道或关闭开关不把旧队列转发给新接收者。已发出或进行中的请求无法撤回。最近记录 7 天后自动清理。

## 权限与隐私

仅管理员和开发者可配置，顾客无权访问。固定 HTTPS 平台地址，禁止任意 webhook；不跟随重定向。密钥存在私有 D1 表，不回显、不写日志、不进入订单导出/通用订单备份/GitHub。依赖平台存储加密，没有额外应用层加密。通知仅含自定义提示、编号、日期场次、需登录的后台链接，不含姓名、电话、微信号、付款截图。别把隐私写进自定义提示。两个站点独立配置，建议只绑定营业主站。

## 发布及验证

执行 `0009_phone_notifications.sql`、`0010_wechat_notifications.sql` 再部署，保留已有每分钟 cron。测试使用隔离 Miniflare 和模拟平台响应，不调用真实推送。绑定真实 token 后仍需收件手机人工验收。Bark 免费开源，第三方服务均不承诺永久免费或必达。
